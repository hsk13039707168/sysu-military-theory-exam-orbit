# 架构与算法说明

本文档说明系统的内部架构、数据流与关键算法。

## 1. 架构定位

系统是一个**单文件、零依赖、纯前端**应用，所有内容（结构、样式、题库数据、业务逻辑）
均内嵌于 `index.html`。这一取舍的核心动机是**分发便利性**：

- 无需安装任何运行环境；
- 单文件便于拷贝、传输、存档与长期保存；
- 不受依赖腐化与网络环境影响。

因此，架构上不引入构建工具、不做模块拆分，代码以「单文件分区」方式组织。

---

## 2. 文件内部结构

`index.html` 依序包含以下区块：

| 区块 | 说明 |
| :--- | :--- |
| `<style>` | CSS 变量主题、布局、组件样式、动画、响应式媒体查询 |
| `<body>` | 页面骨架：角标、导航、容器、Toast |
| `<script>` (数据区) | `BANK` 题库对象、`PAPERS` 真题对象 |
| `<script>` (逻辑区) | 常量、状态、存储、算法、渲染、事件绑定、启动 |

---

## 3. 数据流

```
BANK / PAPERS（静态数据）
        │
        ├──► buildPaper(cfg)   组卷 ──► S.paper（本次试卷）
        │                            │
        │                            ├──► gradeChoice/gradeFill/matchPoints 评分
        │                            │
        │                            ├──► STATS（题号 → 作答统计）──► 低重复抽题
        │                            │
        │                            └──► WRONG（错题本）
        │
        └──► render()  ──► DOM
                  │
                  └──► 用户交互事件 ──► 修改 S ──► 触发 render()
```

### 状态对象 `S`

```js
const S = {
  view: "home",        // 当前视图
  paper: [],           // 当前试卷题目
  idx: 0,              // 当前题号
  answers: {},         // 题号 → 作答
  flags: {},           // 题号 → 标记
  submitted: false,    // 是否已交卷
  startTs: 0,          // 开始时间戳
  leftSec: 0,          // 剩余秒数
  review: false,       // 是否处于解析模式
  result: null         // 评分结果
};
```

采用**单一状态对象 + 整体重渲染**的朴素架构（无虚拟 DOM），因为单页应用规模有限，
DOM 规模可控（单次渲染最多约 60 题），全量重渲染性能充裕且代码量最小。

## 4. 存储层

```js
const LS = { get(key, def), set(key, val) };  // localStorage 薄封装，含异常兜底
```

| 键 | 结构 | 说明 |
| :--- | :--- | :--- |
| `mt.stats` | `{ [qid]: { n, ok, t } }` | 题号 → 作答次数、正确次数、最近时间 |
| `mt.wrong` | `{ [qid]: { t, wrong } }` | 题号 → 首次答错时间、错误次数 |
| `mt.history` | `[{ ts, mode, score, max, sec, detail }]` | 最近 60 次模考记录 |

`LS.set` 包裹 `try/catch`，在 `file://` 协议或隐私模式下 localStorage 不可用时
静默降级，不阻断应用运行。

## 5. 关键算法

### 5.1 智能防重复抽题 `lowRepeatDraw(list)`

目的：在随机抽题基础上，**优先选择历史作答次数少的题目**，降低重复刷题疲劳。

核心思路：按作答次数对候选题目加权，次数越少权重越高；以加权随机方式抽取，
而非均匀随机。作答次数数据来自 `STATS`。

### 5.2 知识点归并 `stemKey(s)`

对题干做归一化处理（剥离空格、标点、大小写差异），生成指纹用于相似题判定。
当多道客观题指纹高度相近时，判定为同一考点的不同问法，组卷时做**同考点限额**处理，
避免一场考试里出现多道等价题。

### 5.3 客观题判分 `gradeChoice(q, ans)`

- `single` / `judge`：答案字母全等即满分，否则零分；
- `multiple`：与标准答案集合做**完全匹配**，多选、少选、错选均不得分。

### 5.4 填空题判分 `gradeFill(q, text)`

先经 `normText()` 归一化（去除空格与中英文标点、统一小写），再与标准答案比对。
用于消除「14年 / 14 年」「《孙子兵法》」这类排版差异造成的误判。

### 5.5 主观题采点评分 `pointsFromAnswer()` / `matchPoints()` / `autoScore())

流程：

1. `pointsOf()` / `keywordsOf()` 从参考答案中**提取关键词与采分点**；
2. 按分值尺度 `scalePoints()` 将采分点分配为若干个采分项，每项带权重；
3. `matchPoints()` 将学生作答与各采分项比对，记录命中情况；
4. `autoScore()` 汇总命中项得分并折算（保留一位小数）。

该机制的局限：关键词匹配不理解语义，**同义表述可能漏判**，
因此主观题得分仅供参考，系统始终展示参考答案供对照。

### 5.6 试卷分值换算 `withExamScores()` / `scoreOf()`

同一题目在「练习模式」与「考试模式」下分值不同（如简答题练习 10 分 / 考试 5 分）。
`withExamScores()` 按当前模式批量换算，`scoreOf(type, mode)` 为单一入口。

## 6. 渲染与路由

采用**哈希无关的内存路由**：`S.view` 在四个视图间切换 —

| 视图 | 说明 |
| :--- | :--- |
| `home` | 首页 / 自定义组卷 |
| `papers` | 刷整套真题 |
| `wrong` | 错题本 |
| `history` | 成绩记录 |
| `exam` | 答题界面（由首页或真题列表进入） |

`go(view, opts)` 负责切换视图并初始化对应状态，`render()` 根据 `S.view`
分派到 `viewHome()` / `viewPapers()` / `viewWrong()` / `viewHistory()` / `viewExam()`。

`pushNav()` / `restoreNav()` 使用 History API 维护浏览器前进后退行为。

---

## 7. 事件绑定

采用**容器级事件委托**：在根容器上监听 `click`，通过 `dataset` 属性
（`data-nav` / `data-paper-start` / `data-chap` / `data-opt` / `data-jump` 等）
分发到具体处理器。避免为动态生成的数百个元素单独绑定监听器。

键盘事件在答题模式下单独监听，并跳过 `INPUT` / `TEXTAREA` 目标，
避免与填空题输入冲突。

---

## 8. 安全设计

- **XSS 防护**：所有来自题库或用户输入的文本，渲染前经 `esc()` 转义
  （`&`、`<`、`>`、`"`、`'` 五字符），模板字符串中不直接插入未转义内容。
- **无网络请求**：应用不调用任何外部接口，无数据外泄路径。
- **无 `eval` / `new Function`**：不存在动态代码执行。
- **无第三方脚本与 CDN**：避免供应链风险。
